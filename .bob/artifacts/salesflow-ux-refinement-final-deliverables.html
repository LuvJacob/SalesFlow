6. Markdown Preview Integration Status

IBM Bob IDE does not expose a programmatic API to open files or trigger Markdown preview from an MCP tool or mode instruction.

What works: The tool returns a workspace_relative_path (e.g., outputs/reports/discovery_brief_...md). SalesFlow includes this as a clickable link in the chat reply along with the preview instruction.

Seller action required (minimal):

  1. Click the link in chat (or open the file from the Explorer sidebar)
  2. Press ⇧⌘V (Mac) or Ctrl+Shift+V (Windows/Linux) for side-by-side Markdown preview

Not implemented (by design): No fragile UI automation, no IDE internal file modification. The rules explicitly document the manual two-step process.

8. Remaining Limitations

  • IDE preview: Cannot be triggered programmatically. Manual open + ⇧⌘V is the current path.
  • SalesFlow mode edit group: The custom_modes.yaml currently has read + mcp groups. The Markdown writing is performed by the save_salesflow_report MCP tool (server-side), so the edit group is not required for file writing to work. The MCP tool handles all I/O.
  • Live IBM retrieval: Not implemented. Product facts are sourced from the static local catalog only.
  • Bob IDE MCP session restart: After changing server.py, the MCP server must be restarted for the new tool to appear. See restart instructions below.
  • 02-spin.md quantity rule: The existing rule specifies 6–10 questions. The new rule clarifies that the chat shows 6–10 while the Markdown report shows exactly 4 (one per type). Both are correct in their context.

9. Bob MCP Server Restart Instructions

After modifying server.py, the Bob IDE MCP session must be restarted for the new save_salesflow_report tool to appear:

  1. Open the Bob IDE Command Palette (⌘⇧P / Ctrl+Shift+P)
  2. Run: MCP: Restart MCP Server → select salesflow
  3. Alternatively, close and re-open the Bob chat panel
  4. Confirm with: ask Bob to ping — status should return ok
